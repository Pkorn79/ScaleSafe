Troubleshooting

What to capture before reporting a ScaleSafe issue.

Checkout or payment issue

Payment failed, duplicated, or returned an unexpected error

  • Capture the merchant/sub-account, client, offer, checkout URL, processor, and exact time.
  • If money moved, include the Stripe payment intent/charge ID or NMI transaction ID.
  • Check whether ScaleSafe created a payment event, enrollment, saved payment method, and processor subscription ID.
  • For duplicate-charge concerns, confirm processor charge count and ScaleSafe payment event count.
Workflow issue

Receipt, enrollment link, reminder, pulse, or refund workflow did not fire

  • Confirm the GHL workflow is published and uses the correct ScaleSafe Marketplace trigger.
  • Check ScaleSafe Provisioning Health for active trigger subscription count.
  • Review trigger delivery logs for sent, failed, or no-subscription status.
  • For app events, confirm the workflow filter matches the event type, such as upcoming_payment_reminder or pulse_check_due.
NMI setup

NMI card shows unknown brand or expiration

  • Confirm the NMI security key has Query API permission enabled.
  • Run a fresh vaulting transaction after enabling Query API. Old rows may not backfill automatically.
  • Confirm the payment method shows the vault ID, brand, and expiration in ScaleSafe.
Recurring payments

Subscription ID missing or reminders did not send

  • Confirm the processor subscription exists in Stripe or NMI.
  • Confirm ScaleSafe saved the processor subscription ID on the enrollment.
  • Check billing setup status. Reminders are skipped when billing is not ready.
  • Confirm the next billing date is inside the reminder window.
